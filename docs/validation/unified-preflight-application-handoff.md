## Entry points and cooperative enforcement trace

See [`unified-preflight-execution.md`](unified-preflight-execution.md) for the
complete executable procedure and precise boundary.

1. **First action after Start:** Agent reads the actual complete native task,
   policy, contract, seal, scope, current lifecycle and applicable owner
   authorization. Current host tools `getProjectTask`/`updateProjectTask` are
   available to the Agent, not invented Node/shell APIs.
2. **Prepare, do not admit:** `prepare-plan.mjs candidate-and-inspection.json`.
   Concrete inspected fields, scenarios/assertions and required workload steps
   produce a candidate or explicit refusal. No generic stub, fabricated
   coverage/approval, allocation or sealed rewrite. Adequate unavailable tiers
   remain unavailable. Unchanged valid plans return reuse.
3. **Provision/amend through supported routes:** new drafts use `new-plan.mjs`.
   Current amendments require the old observed context plus concrete
   authorization applicability/evidence-impact notes; these are audit notes,
   not an approval service. Native identity is preserved, current revision
   rechecked, old/new targets excluded, and existing run uncertainty refuses.
4. **Reconcile native dispatch:** preserve original approved scope, update the
   exact sealed JSON payload through the supported host task writer, read the
   full result back and compare. Partial host/local reconciliation blocks.
   Description-only edits never alter the local seal or binding.
5. **Read-only admission component:**
   `TASK_PLAN_FILE=... UNIFIED_CONTEXT_FILE=... node scripts/check-unified-preflight.mjs ID`.
   Local PASS explicitly reports host authorization/lifecycle NOT_OBSERVED.
   JSON supplies exact plan inputs only; caller-created approval fields reject.
6. **Immediately before dispatch/resumption:** repeat actual host checks;
   `dispatch-implementation.mjs ID bounded-command.json` rechecks expected local
   revision under its target lease and uses finite process-tree supervision.
   Programmatic dispatch shares that local boundary. Direct editor batches remain
   Agent-cooperative; no claim of an atomic lock over Replit editor tools.
7. **Validation:** plan guards, all four tier wrappers, run/retry/RG/classification
   receive expected context for newly governed records. Historical contracts are
   not silently upgraded. Run only the full bound workload; raw/assessed/retry
   results remain distinct and relevant evidence changes need renewal.
8. **Post-Start gap:** pause affected work, preserve observations/edits, establish
   quiescence, prepare/amend/reconcile/re-admit, reassess prior edits and renew
   affected checks. No unrelated target stop or retrospective authorization.

`UNIFIED_CONTEXT_FILE` is not host authentication. A forged payload matching local
bytes cannot prove approval/lifecycle; the checker never says it can. Meaningful
approval/coverage decisions are not converted into a CLI flag, JSON boolean,
agent-authored authority receipt or general natural-language approval engine.
