## Decision summary

CloudPainter has a real native Replit Project Tasks interface and real validation callers, but neither establishes a project-local Failure Gate decision or tier. The repository contains no Failure Gate Core runtime, registry, store, checked runner, completion checker, or Core recovery route. Existing CI and browser harness controls have limited scopes and cannot be reused as Core approval or bootstrap permission.

Governance is **UNKNOWN**, not ACTIVE and not INACTIVE. The canonical Failure Gate v4 definition is present. The owner's direction, retained in Task #399's native plan, is to remove that package **if** it is independently shown to be non-controlling and free of required live dependencies, or at an approved transition boundary. That is conditional retirement intent; it does not establish that v4 is non-controlling now. Prior host execution authority remains unverified. Do not remove v4, infer Core adoption, activate a policy, or use a Replit task status as approval.

The PostgreSQL module and CloudPainter application database are visible host/application capabilities, not an authorized Core store. No database has been selected. The browser-local sketch backup and the disposable PostgreSQL service in CI are unrelated to durable Core evidence and recovery.

## Status key

- **PRESENT** — a specific interface or resource exists in the inspected source/record, for the stated limited purpose.
- **UNAVAILABLE** — no usable project-local Core route was found in the inspected sources. This does not claim Replit or another external host could never supply one.
- **UNKNOWN** — evidence needed to establish the capability or controlling authority is not exposed by the inspected sources/read-only records. Unknown is not a denial or proof of inactivity.
- A required **UNAVAILABLE** or **UNKNOWN** capability is **BLOCKED** for Core use. A nearby tool, task status, fixture, or app service is not a substitute.
