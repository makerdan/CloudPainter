The existing current-contract `self` declaration supports an optional structured
`regressionAssessment.verification`, serialized by the unchanged v4 renderer.
It requires:

- `target`: repository-relative regular-file path and pinned SHA-256.
- `source`: independent approved path and SHA-256; an optional exact ZIP member
  requires its own SHA-256. No arbitrary command, extraction or wildcard member.
- `method`: concrete reproducible inspection procedure.
- `assertions`: unique IDs, concrete assertion text, and explicit expectations.
  Supported kinds are `bytes-equal` (expected `equal`) and `contains` (expected
  literal text). At least one byte comparison is mandatory.
- `observationsLocation`: separate repository-relative observation record.
- `repairPolicy`: exactly `stop-and-amend-before-correction`.

Preparation, provisioning, same-reservation completion, amendments, plan guards,
preflight and runner admission share `assessRegression`. The existing executable
check-file safeguard remains for self declarations without a structured method.
Material scope assessment remains mandatory. An additional conservative no-change
scope check rejects active correction and policy/behavior directives. Read-only
comparison vocabulary was added to the existing finite neutral-procedure list;
unknown operations remain visible and cannot hide behind an inspection prefix.

At planning, results are not required. At delivery, the observation record names
the task ID, exact seal hash, method hash, observed timestamp, current snapshot,
an actual observation for each assertion and explicit limitations. Snapshots
recompute file/member hashes and actual byte/content outcomes with finite bounds.
Missing, generic, partial, failed or stale observations deny workload launch.
The runner repeats the delivery check under its existing target lease and before
PASS, retaining the delivery fingerprint in its report. Source drift during
execution cannot produce a successful final validation result.

`check-verification-delivery.mjs ID` is the read-only delivery check with the
existing exact native/sealed context. It performs normal preflight first and
reports source observations, not a tier PASS or host approval. Observation files
are cooperative executor evidence, not authenticated proof of prose or platform
enforcement. Semantic inspection and actual host authorization remain Agent duties.
